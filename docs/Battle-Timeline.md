# 公会战打轴开发版

在公主连结国服安卓端手动编队，停在「队伍编组」页。让 MFAAvalonia 连接该设备，运行「公会战打轴（开发版）」。编辑器会显示当前队伍的画面。选择角色人数，勾选开场 AUTO 和 SET，再逐行添加倒计时、释放 UB 的槽位和调整后的 SET。点击编辑器的「开始战斗」后，程序重新识别编组页和「战斗开始」，确认后点击一次。

槽位按画面从左到右排列，五人队的顺序是 5、4、3、2、1，1 号是前排。每行 SET 是五个槽位的完整目标状态。`XOXXO` 表示只开 4 和 1 号位。编辑器可以打开和另存 JSON，开始前会将当前轴保存到包内 `config/battle-timeline.json`。同秒的多行按列表顺序匹配独立的 UB 事件。

## 识别与执行

- 以 16:9、1280×720 的国服画面为识别基准。MaaFramework OCR 读右上角的游戏倒计时，动画期间允许倒计时停在同一秒。结算通过「伤害报告」和「下一步」联合识别。
- Python 通过 HP 和蓝色 TP 条的边框定位槽位。SET 读取角色头像右上方的「立即发动」徽标和边框。AUTO 读取右侧按钮的颜色。
- UB 候选要求同槽位 TP 由 84% 以上降至 38% 以下，并且下降至少 52 个百分点。两次有效采样的游戏倒计时间隔最多一秒，实际时间间隔最多八秒。阈值是开发版初值。TP 剧烈下降也可能来自其他游戏机制。
- 一行触发后只操作需要变化的开关，每次点击后重新截图确认。批量 SET 点击未得到确认时，会读取每个角色的徽标，逐一调整仍有差异的槽位。过了目标秒仍未观测到该槽位的 UB 时结束执行。日志位于包内 `debug/battle-agent.log`。

当前素材为五人练习战。编辑器允许 1–5 人并在开场核对检测到的槽位数。1–4 人的实际战斗 HUD 仍需采样。调试时在「大家的训练场」选择当前最高阶段，避免首领在后续轴行触发前被击败。UB 动画、特效遮挡和截图延迟会影响同秒多次动作的识别。

## 调试截图

勾选编辑器里的「保存调试截图」，程序会在点击开始战斗、调整 AUTO 或 SET，以及确认开场或轴行完成后，等待 0.1 秒再请求截图。截图保存在包内 `debug/battle-steps/`，每场战斗使用独立的时间戳目录，按步骤顺序命名。PNG 由后台保存，采集到的画面会复用给下一次识别。

## 文件格式

```json
{
  "version": 1,
  "title": "练习轴",
  "team_size": 5,
  "auto": true,
  "initial_set": "OOOOO",
  "debug_screenshots": false,
  "steps": [{"time": "1:20", "slot": 3, "set": "XOXXO"}]
}
```

维护识别时优先使用本机练习战录屏，保留倒计时与 5→1 的槽位映射。自动测试使用程序生成的画面和输入序列。用户录像存放在本地 `install/`。
